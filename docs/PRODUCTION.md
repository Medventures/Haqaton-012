# Подготовка к развёртыванию PRIME

## Статус

Репозиторий содержит серверную интеграцию агента, ограничения запросов, конфигурацию окружения, контейнер и проверяемые метрики. Это техническая основа для пилота. Допуск к обработке реальных медицинских данных и клиническому использованию требует отдельного решения клиники.

Календарь, цены и результаты обследований остаются демонстрационными. Docker-запуск сам по себе не подключает медицинскую информационную систему и не подтверждает клиническую готовность.

## 1. Секреты и окружение

Ключ называется `OPENAI_API_KEY`. Храните его в серверном `.env` либо в менеджере секретов среды размещения. Не помещайте ключ в JavaScript, документацию, Git, скриншоты или контейнерный образ. Если `.env` уже существует, дополняйте его: не заменяйте файлом примера поверх действующего ключа.

Основные настройки:

| Переменная | Назначение |
|---|---|
| `OPENAI_API_KEY` | Серверный ключ OpenAI |
| `OPENAI_MODEL` | `gpt-5-mini` по умолчанию; изменение модели требует повторной проверки сценариев |
| `OPENAI_TIMEOUT_SECONDS` | 35 секунд на один вызов; допустимо 5–90 |
| `MEDHUB_AGENT_ENABLED` | `false` отключает внешние вызовы и оставляет сценарий по правилам |
| `MEDHUB_ENV` | `production` для развёртывания |
| `MEDHUB_HOST`, `MEDHUB_PORT` | Интерфейс и порт; локально `127.0.0.1:8000` |
| `MEDHUB_ALLOWED_ORIGINS` | Точные адреса сайта через запятую, без пути и масок; production требует `https://` |
| `MEDHUB_SIGNING_SECRET` | Случайный секрет не менее 32 символов; одинаковый для экземпляров одной среды |
| `MEDHUB_RATE_LIMIT` | 20 запросов в окне по умолчанию |
| `MEDHUB_RATE_WINDOW_SECONDS` | Окно ограничения, по умолчанию 60 секунд |
| `MEDHUB_MAX_CONCURRENT_AGENTS` | 4 одновременные обработки моделью на процесс по умолчанию |
| `MEDHUB_THREADS` | 8 потоков сервера по умолчанию |
| `ADMIN_TOKEN` | Отдельный случайный токен 32+ символа для закрытой сводки метрик |
| `MEDHUB_METRICS_DB` | Путь к SQLite; по умолчанию `data/metrics.sqlite3` |

Секрет подписи и административный токен должны быть разными. Пример команды генерации одного значения:

```powershell
python -c "import secrets; print(secrets.token_urlsafe(48))"
```

Команда предназначена администратору в закрытом терминале. Не сохраняйте её вывод в публичный отчёт. Ротация `MEDHUB_SIGNING_SECRET` делает ранее выданные вопросы недействительными: пользователю потребуется получить новый вопрос.

## 2. Локальная проверка

Из каталога с `server.py`:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -B -m unittest discover -s tests -v
.\.venv\Scripts\python.exe server.py
```

Откройте `http://127.0.0.1:8000`. Проверьте взрослую анкету, анкету родителя, свободный ответ, пропуск, отказ от внешнего ИИ и отказ провайдера. Для проверки модели используйте только вымышленные данные.

Сервер запускается через Waitress. Встроенный отладочный сервер Flask не предназначен для production. [Рекомендации Flask по развёртыванию](https://flask.palletsprojects.com/en/stable/deploying/).

## 3. Контейнер и HTTPS

До запуска задайте production-настройки и секреты в среде размещения. Compose использует сервис `prime`, публикует порт на `127.0.0.1:8000` и сохраняет метрики в том `metrics`, смонтированный в `/app/data`.

```powershell
docker compose build
docker compose up -d
docker compose ps
```

Поставьте перед приложением обратный прокси с TLS и действующим сертификатом. Сам порт приложения не должен быть открыт в интернет. HTTPS обязателен для реальных пользовательских данных.

Для потока `/api/agent` отключите буферизацию ответа. Тайм-аут прокси должен превышать общий 90-секундный предел операции агента с запасом на передачу; 240 секунд достаточно для текущих ограничений. Не записывайте тела запросов, Authorization и подписанные токены в журналы прокси.

В текущей конфигурации приложение не доверяет произвольному `X-Forwarded-For`. За прокси все пользователи могут делить один локальный лимит. Настройте ограничение запросов на границе сети по реальному клиенту; затем задайте подходящий внутренний лимит. Не включайте доверие к заголовкам от непроверенных источников.

## 4. Наблюдение и ограничения

| Проверка | Значение |
|---|---|
| `GET /healthz` | Процесс отвечает |
| `GET /readyz` | Проверка доступности базы метрик; при ошибке базы — 503. `ai_configured` означает наличие настроек, а не проверенный баланс или успешный вызов OpenAI |
| `GET /api/metrics` | Закрытая сводка, заголовок `Authorization: Bearer <ADMIN_TOKEN>` |

Не вызывайте платную модель на каждом запросе мониторинга. Перед питчем или выпуском выполните отдельную проверку синтетической анкеты, чтобы проверить ключ, доступ к модели и квоту.

Панель `/metrics.html` использует отдельный административный токен. Не вводите в ней ключ OpenAI. Не оставляйте административную панель открытой на общем устройстве.

Ограничения сейчас действуют в пределах процесса. Для нескольких экземпляров потребуется общий ограничитель запросов и конкуренции, а также согласованное хранилище метрик. SQLite рассчитан здесь на небольшой пилот с одним экземпляром. HMAC-секрет должен быть общим, иначе вопрос одного экземпляра не будет принят другим.

Установите бюджет и оповещения в проекте OpenAI. Оркестрация делает несколько последовательных вызовов на пациента; сравнивайте стоимость полного сценария, а не цену одного запроса. Отдельно наблюдайте задержку, долю запасного режима, ошибки провайдера и отказы проверки, не сохраняя медицинские тексты в журналах.

## 5. Хранение и обработка данных

Метрики сохраняют только время события, тип сценария, ID программы, длительность и оценку. Имена, ИИН, адреса, IP, медицинские ответы и произвольный текст схема не принимает. Срок хранения метрик — 90 дней; удаление старых записей выполняется при следующем чтении или записи. Если процесс остановлен, отдельный планировщик очистки не работает.

Демо-отчёт и запись используют `sessionStorage` текущей вкладки. Кнопка «Удалить мои ответы» очищает данные проекта в браузере; она не удаляет ранее скачанные файлы, события в личном календаре или запросы у внешнего провайдера.

Для резервной копии работающей SQLite используйте механизм резервного копирования SQLite, либо останавливайте приложение перед копированием базы. Простое копирование только основного файла при активном режиме WAL может пропустить последние записи. Проверяйте восстановление на отдельном экземпляре.

Согласие в интерфейсе должно ясно описывать передачу ответов внешнему помощнику. Отказ сохраняет доступ к подбору по правилам. Не вводите реальные сведения пациентов до согласования текста согласия, условий работы с провайдером, сроков хранения и допустимой инфраструктуры с ответственными лицами клиники.

Запросы используют `store: false`. Это не обещание нулевого хранения у OpenAI: стандартные механизмы мониторинга и дополнительные настройки организации регулируются отдельно. Уточняйте фактические настройки проекта и соглашения перед пилотом. [Документация OpenAI об обработке данных](https://developers.openai.com/api/docs/guides/your-data).

## 6. Что клиника должна подтвердить до пилота

- Каталог пакетов, текущие цены, показания и правила выбора, включая детскую ветвь.
- Тексты срочной помощи, основания перенаправления к врачу и обработку неопределённых ответов.
- Что повторный визит назначается по согласованным медицинским правилам; календарное напоминание не заменяет назначение врача.
- Согласие на обработку данных, роль родителя и условия внешней обработки.
- Кто разбирает ошибки помощника, принимает жалобы и может отключить внешнюю модель.
- Подключение реальных слотов и подтверждение записи, затем статусы оплаты и визита.
- Определения четырёх метрик, исходные значения и критерии прекращения пилота при обнаружении проблемы.

## 7. Проверка перед выпуском

1. Запустить все тесты и проверить реальные ответы API на вымышленных данных.
2. Убедиться, что `.env`, база метрик и служебные файлы недоступны через HTTP и не входят в образ/Git.
3. Проверить production-конфигурацию: HTTPS origins, секрет подписи, отдельный административный токен, ограничение тела запроса и частоты.
4. Проверить в браузере мобильную и настольную версию, клавиатуру, отказ от ИИ, пропуск вопроса, изменение анкеты и истёкший токен.
5. Симулировать недоступность модели: пользователь должен получить объяснённый запасной сценарий, без ложной отметки «проверено ИИ».
6. Убедиться, что метрики с нулевыми данными не показывают вымышленные продажи или улучшение здоровья.
7. Получить согласование клиники для реального пилота и развернуть в выбранной ею среде.

## 8. Откат

Для быстрого отключения внешней модели установите `MEDHUB_AGENT_ENABLED=false` и перезапустите сервис. Подбор по правилам продолжит работать. Для отката релиза разверните предыдущий проверенный образ с совместимой конфигурацией. Сохраните закрытую резервную копию метрик; не включайте данные или секреты в публичную историю инцидента.
