# ПРАЙМ — чекап по карте здоровья

Демонстрационный MVP для хакатона. Пациент открывает готовую карту, получает объяснимый подбор чекапа, видит пакеты с ценами и выбирает время с минимальной расчётной загрузкой. После визита сервис показывает историю и предлагает добавить в календарь контакт с врачом через шесть месяцев. Панель клиники считает продажи, время прохождения, повторные визиты и удовлетворённость.

## Запуск

Требуется Python 3.10 или новее. Зависимостей для установки нет.

```powershell
cd C:\Users\bekza\Desktop\medhub\MedHub_CheckUp
python server.py
```

Откройте `http://127.0.0.1:8000`. Для остановки нажмите `Ctrl+C`.

Проверка логики:

```powershell
python -m unittest discover -s tests -v
```

## Что работает в демо

- Три вымышленные карты содержат историю визитов, известные заболевания, лекарства, семейные сведения и показатели в динамике. Подбор использует эти данные; анкету заполнять не нужно.
- Пять программ и цены взяты из [официального прайса PRIME Green Clinic](https://primegc.kz/price-list-strahovie/): мужской базовый — 355 700 ₸, женский базовый — 358 020 ₸, мужской расширенный — 467 100 ₸, женский расширенный — 479 900 ₸, «Сердце» — 257 840 ₸. Клиника подтверждает итоговую цену и состав.
- Демонстрационный календарь сортирует доступные окна по ожидаемому времени ожидания. Запись резервируется в локальной базе SQLite с проверкой вместимости окна.
- После демонстрационного завершения визита обновляются оплаченные чекапы, выручка, длительность и повторы. Оценка пациента обновляет показатель удовлетворённости. Исходная статистика синтетическая и явно помечена как демонстрационная.
- Через шесть месяцев от визита можно скачать событие календаря для обсуждения с врачом необходимости следующего чекапа. Это напоминание о контакте, а не медицинское назначение проходить обследование каждые шесть месяцев.

## Подключение данных клиники

Публичного подтверждённого доступа к полной карте ДамуМед по одному ИИН для этого проекта нет. Получать медицинские данные только по ИИН нельзя: нужна авторизация, согласие пациента и согласованный интерфейс обмена. Поэтому приложение не запрашивает ИИН и не изображает подключение к ДамуМед. Для рабочей версии клинике нужно предоставить:

1. Защищённый способ идентификации пациента и его согласие на доступ к карте.
2. Документацию и доступ к системе карт: возраст, история визитов, диагнозы, лекарства, аллергии, анализы, даты и источники данных.
3. Документацию календаря: свободные окна по программе и ресурсам, существующие записи, создание и отмена брони.
4. Подтверждение актуального прайса и правил оплаты, чтобы считать реальные продажи, а не только заявки.

Точки замены в коде: `DEMO_PROFILES` и `get_profile` в `domain.py`; `_candidate_slots`, `get_slots`, `create_booking` в `storage.py`. Для рабочего подключения также потребуются роли сотрудников, защита карт и журнал доступа. Сейчас API слушает только `127.0.0.1` и содержит исключительно вымышленные карты.

Метрики за 30 дней рассчитываются из таблиц `recommendations` и `bookings`: продажи — записи с оплатой, длительность — разница между входом и завершением, повторы — завершённые визиты с прежним чекапом, удовлетворённость — средняя оценка от 1 до 5. База создаётся как `demo.sqlite3` при первом запуске.
