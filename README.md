# PRIME — конструктор check-up с персональным агентом

**Анкета → одно точное уточнение → пакет PRIME → маршрут на день → карта здоровья → напоминание.**

Приложение для пациентов в Казахстане. Интерфейс на русском; бренд PRIME и термин check-up сохранены на английском. Анкету ребёнка заполняет родитель. Пакеты и цены заданы каталогом, а агент помогает подготовить первую беседу с врачом.

## Запуск на Windows

Нужен Python 3.10+. Из каталога проекта:

```powershell
cd C:\Users\bekza\Desktop\medhub\MedHub_CheckUp
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe server.py
```

Откройте **http://127.0.0.1:8000**. Остановка — `Ctrl+C`. Используется Flask с сервером Waitress; зависимости закреплены в `requirements.txt`.

### Ключ и настройки

Если `.env` уже существует, дополните его, сохранив ключ. Для новой установки создайте `.env` по образцу `.env.example` и задайте:

```dotenv
OPENAI_API_KEY=ваш_серверный_ключ
OPENAI_MODEL=gpt-5-mini
OPENAI_TIMEOUT_SECONDS=35
MEDHUB_AGENT_ENABLED=true
MEDHUB_ENV=development
```

`OPENAI_API_KEY` используется только сервером. Не добавляйте `.env` в Git и не вставляйте ключ в браузерный код. Без ключа приложение работает по правилам. Переменные окружения имеют приоритет над `.env`.

## Что делает настоящий агент

После согласия пользователя сервер вызывает OpenAI Responses API:

1. **Интервьюер** читает ответы, каталог и исходный маршрут через три ограниченных инструмента. Находит недостающую деталь и формулирует один вопрос, учитывая свободный текст.
2. **Проверяющий** отдельным вызовом сверяет вопрос с источниками. Допускается одна попытка исправления.
3. После ответа **составитель записки** показывает, что было неизвестно и что прояснилось, готовит задачу первой консультации.
4. **Повторная проверка** сверяет записку с действительным ответом. Для записки также допускается одна попытка исправления: после ошибки формата или замечаний проверяющего. Результат появляется в плане и карте здоровья.

В интерфейсе видны реальные этапы и результат **«до уточнения → после ответа»**. Вопрос подписывается сервером и связан с конкретной анкетой. Можно ответить своими словами, выбрать вариант, пропустить или вернуться назад.

Режимы обозначаются честно:

- С согласия пользователя и работающей моделью — персональный вопрос и записка от ИИ.
- Без согласия или при отключённой модели — подготовленное уточнение по правилам, без передачи анкеты OpenAI.
- При ошибке внешнего сервиса — объяснённый запасной сценарий. Он не выдаётся за успешный ответ модели.

Пакет, состав и цена контролируются приложением. Агент не ставит диагноз, не назначает лечение и не добавляет услуги ради увеличения чека. [Подробная архитектура и промпты](docs/ARCHITECTURE.md).

## Демонстрация

Используйте вымышленные данные: взрослый, 36 лет, усталость и давление; свободный ответ — «Работаю посменно. Давление обычно измеряю вечером, когда уже отдохнул». После уточнения покажите связь с анкетой, изменение плана и записку для врача. Точная формулировка модели может меняться.

Пакеты для демонстрации: базовый — **59 900 ₸**, расширенный — **89 900 ₸**, «Сердце» — **69 900 ₸**, детский — **49 900 ₸**. Это не официальный прайс клиники.

Календарь показывает вымышленные слоты и нагрузку. Файлы `.ics` добавляют план и напоминание в личный календарь; настоящей записи в клинику не создают. Карта здоровья содержит демо-отчёт, а не загруженные медицинские результаты. Частоту последующих обследований определяет врач.

Отчёт и демонстрационная запись хранятся в `sessionStorage` текущей вкладки. Кнопка **«Удалить мои ответы»** очищает данные проекта в браузере; она не удаляет скачанные файлы календаря или ранее переданные провайдеру запросы. Для сохранения плана доступна печать.

[Питч на 90 секунд, сценарий показа и ответы жюри](docs/PITCH.md).

## Метрики клиники

Закрытая панель — **http://127.0.0.1:8000/metrics.html**. Задайте отдельный случайный `ADMIN_TOKEN` длиной не менее 32 символов и введите его в панели. Это не API-ключ OpenAI; серверный ключ браузеру не выдаётся. Без административного токена сводка закрыта.

| Цель | Что измеряется сейчас |
|---|---|
| Продажи | Интерес к записи и его отношение к событиям рекомендации; оплат и выручки пока нет |
| Время | Длительность пользовательского сценария и обработки помощником; время в клинике ещё не измеряется |
| Повторные визиты | Создание напоминаний; факт повторного посещения требует интеграции |
| Удовлетворённость | Добровольная оценка полезности подбора от 1 до 5 |

SQLite хранит только разрешённые события, тип сценария, ID пакета, длительность и оценку, без анкеты, свободного текста и идентификаторов. Срок хранения — 90 дней. Счётчики не определяют уникальных пациентов и не доказывают рост продаж.

## Проверки

Тесты без платных запросов:

```powershell
.\.venv\Scripts\python.exe -B -m unittest discover -s tests -v
```

Проверки интерфейса в установленном Chrome (сервер должен работать в отдельном терминале):

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe scripts/browser_smoke.py --base-url http://127.0.0.1:8000
.\.venv\Scripts\python.exe scripts/metrics_smoke.py --base-url http://127.0.0.1:8000
```

Эти браузерные сценарии подставляют синтетические ответы API и не отправляют запросы модели. Они проверяют взрослую и детскую анкеты, уточнение, отмену, ошибки, план, календарь, мобильную вёрстку и доступ к панели клиники.

Проверка настоящей модели на синтетических анкетах делает платные запросы к OpenAI:

```powershell
.\.venv\Scripts\python.exe scripts/eval_agent.py --live
```

Полный браузерный сценарий с настоящим ИИ и сохранением снимков экрана в `.qa-screenshots/`:

```powershell
.\.venv\Scripts\python.exe scripts/live_browser_demo.py --live --base-url http://127.0.0.1:8000
```

Для одного сценария добавьте к `eval_agent.py --live` параметр `--case night-shifts`; доступны также `child-vision`, `recent-results`, `urgent`. По умолчанию этот скрипт выводит результат и длительность без ключей и текстов анкет. Успешный единичный прогон подтверждает работу интеграции в этот момент и не является клинической валидацией.

Для диагностики добавьте к `eval_agent.py --live` флаг `--diagnose`: он выводит созданные ИИ вопросы и замечания проверки только для заранее встроенных вымышленных сценариев. Ключи, заголовки запросов, внутренние рассуждения и подписанные токены не выводятся; диагностические тексты не сохраняются в файлы.

## Развёртывание

Подготовлены `Dockerfile`, `compose.yaml`, production-проверки конфигурации, `/healthz` и `/readyz`. Локальная сборка контейнера в текущем окружении не проверялась: Docker недоступен. `/readyz` проверяет доступ к базе; `ai_configured` сообщает только о настройке ключа, а не о доступности провайдера.

Для production нужны HTTPS, точные `MEDHUB_ALLOWED_ORIGINS`, случайный `MEDHUB_SIGNING_SECRET`, отдельный административный токен и ограничения на обратном прокси. Ограничитель приложения действует на процесс и IP непосредственного подключения; за прокси пользователи могут делить один лимит. [Запуск, ограничения, данные и подготовка клинического пилота](docs/PRODUCTION.md).

Дамумед, реальные расписания, оплаты и отправка напоминаний внешними каналами пока не подключены. Работа с реальными пациентами требует согласования клинических правил и обработки данных с клиникой.

## Файлы

- `domain.py` — каталог, анкеты, правила подбора и маршрут.
- `agent_engine.py`, `agent_prompts.py` — оркестрация модели, инструменты, проверка и подпись.
- `assistant_logic.py` — запасной помощник по правилам.
- `server.py`, `config.py` — API, поток этапов, ограничения и настройки.
- `metrics.py` — события и закрытые агрегаты.
- `public/` — анкета, агент, пакеты, календарь, карта здоровья и панель метрик.
- `tests/`, `scripts/eval_agent.py` — автоматические проверки и явная проверка провайдера.

Код приложения — MIT. Flask и Waitress имеют открытый исходный код; облачная модель OpenAI является внешним сервисом с отдельными условиями. Это следует учитывать при согласовании требования трека к открытому стеку.
